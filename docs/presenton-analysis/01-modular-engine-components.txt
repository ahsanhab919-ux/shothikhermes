A. APPLICATION BOOTSTRAP AND MIDDLEWARE CHAIN
================================================================================

--------------------------------------------------------------------------------
A1. server.py
--------------------------------------------------------------------------------
Path: servers/fastapi/server.py
Responsibilities:
  - Entry-point script for launching the FastAPI application via uvicorn.
  - Parses CLI arguments: --port (required), --reload, --log-level.
  - Imports the FastAPI `app` object from api.main and runs uvicorn on
    127.0.0.1:<port>.
Key Dependencies:
  - uvicorn (ASGI server)
  - api.main (imports the app object)
Execution Flow:
  1. argparse parses --port, --reload, --log-level.
  2. uvicorn.run("api.main:app", host="127.0.0.1", port=..., ...) is called.
  3. Uvicorn imports api.main, which triggers app construction at module load
     time (see A3 below).
Role in System:
  - Thin launcher; no business logic. In Docker/Electron this is replaced by
    a process manager or PyInstaller bundle (see server.spec).

--------------------------------------------------------------------------------
A2. api/lifespan.py — app_lifespan
--------------------------------------------------------------------------------
Path: servers/fastapi/api/lifespan.py
Responsibilities:
  - Defines the FastAPI lifespan context manager (app_lifespan) that runs
    startup and shutdown logic.
  - Startup sequence (in order):
    a. _configure_application_logging() — sets root logger level from LOG_LEVEL
       env, inherits uvicorn handlers.
    b. Creates APP_DATA_DIRECTORY if missing.
    c. migrate_database_on_startup() — runs Alembic migrations if
       MIGRATE_DATABASE_ON_STARTUP=true.
    d. create_db_and_tables() — creates missing SQLModel tables if Alembic is
       not used.
    e. import_default_templates_on_startup() — seeds bundled templates into DB.
    f. _bootstrap_auth_from_env() — sets up single-user login from
       AUTH_USERNAME/AUTH_PASSWORD env vars; supports RESET_AUTH and
       AUTH_OVERRIDE_FROM_ENV.
    g. update_env_with_user_config() — loads user-config overrides into env
       (unless CAN_CHANGE_KEYS=false).
    h. check_llm_and_image_provider_api_or_model_availability() — validates
       that the configured LLM and image providers are reachable.
  - Shutdown: dispose_engines() to release DB connection pools.
Key Dependencies:
  - migrations.migrate_database_on_startup
  - services.database (create_db_and_tables, dispose_engines)
  - templates.default_templates (import_default_templates_on_startup)
  - utils.get_env, utils.model_availability, utils.user_config,
    utils.simple_auth
Execution Flow:
  FastAPI calls app_lifespan(app) at startup. The context manager yields after
  completing all init steps, then runs dispose_engines() on shutdown.
Role in System:
  - Orchestrator of all startup side-effects. Guarantees DB, auth, templates,
    env, and provider availability before the app accepts requests.

--------------------------------------------------------------------------------
A3. api/main.py — app
--------------------------------------------------------------------------------
Path: servers/fastapi/api/main.py
Responsibilities:
  - Constructs the FastAPI application object (`app`).
  - Optionally initializes Sentry (if SENTRY_DSN is set).
  - Initializes sandbox-safe mimetypes (init_sandbox_safe_mimetypes).
  - Registers all v1 API routers:
      API_V1_PPT_ROUTER, API_V1_WEBHOOK_ROUTER, API_V1_MOCK_ROUTER,
      API_V1_AUTH_ROUTER, API_V1_ASYNC_TASKS_ROUTER
  - Mounts static file directories:
      /app_data -> APP_DATA_DIRECTORY (user-generated assets)
      /static  -> static/ (bundled icons, images, placeholders)
  - Configures CORS (origins from NEXT_PUBLIC_URL or wildcard).
  - Adds two custom middlewares (in order):
      1. UserConfigEnvUpdateMiddleware (added first, runs outer)
      2. SessionAuthMiddleware (added second, runs inner)
  - Adds a function-level middleware for static icon 404 fallback
    (serves placeholder.svg when /static/icons/* returns 404).
Key Dependencies:
  - fastapi.FastAPI, fastapi.middleware.cors.CORSMiddleware,
    fastapi.staticfiles.StaticFiles
  - api.lifespan.app_lifespan
  - api.middlewares (SessionAuthMiddleware, UserConfigEnvUpdateMiddleware)
  - All v1 routers (ppt, webhook, mock, auth, async_tasks)
  - utils.get_env, utils.mime_types, utils.path_helpers
Execution Flow:
  Module load: init_sandbox_safe_mimetypes() -> _maybe_init_sentry() ->
  app = FastAPI(lifespan=app_lifespan) -> include_router() x5 ->
  mount() x2 -> add_middleware() x2 -> @app.middleware() for icon fallback.
  At request time: CORS -> UserConfigEnvUpdateMiddleware ->
  SessionAuthMiddleware -> icon_fallback_middleware -> route handler.
Role in System:
  - Application factory. Single source of truth for router registration,
    middleware chain, and static asset serving.

--------------------------------------------------------------------------------
A4. api/middlewares.py
--------------------------------------------------------------------------------
Path: servers/fastapi/api/middlewares.py
Responsibilities:
  - UserConfigEnvUpdateMiddleware: on every request, calls
    update_env_with_user_config() to refresh env vars from the persisted user
    config file (unless CAN_CHANGE_KEYS=false). Ensures runtime config changes
    take effect without restart.
  - SessionAuthMiddleware: enforces single-user session/basic-auth.
    - Exempt paths: /api/v1/auth/*, OPTIONS requests, public app_data paths
      (/app_data/images/, /app_data/fonts/, /app_data/pptx-to-html/).
    - Protected paths: all /api/* paths, /docs, /openapi.json, /redoc, and
      non-public /app_data/ paths.
    - Auth flow:
      1. If DISABLE_AUTH=true, pass through.
      2. If auth not configured, return 428 (setup_required).
      3. Check session token from request. If valid, set auth_username and
         pass through.
      4. Fall back to HTTP Basic Auth. If valid, set auth_username and pass.
      5. Otherwise return 401 Unauthorized.
Key Dependencies:
  - starlette.middleware.base.BaseHTTPMiddleware
  - utils.get_env (get_can_change_keys_env, is_disable_auth_enabled)
  - utils.simple_auth (get_auth_status, verify_credentials, etc.)
  - utils.user_config (update_env_with_user_config)
Execution Flow:
  Request -> UserConfigEnvUpdateMiddleware.dispatch (refresh env) ->
  SessionAuthMiddleware.dispatch (validate session/basic auth) ->
  route handler.
Role in System:
  - Security gate. Every API request passes through both middlewares.
  - Config freshness gate. Ensures user config is loaded before each request.

B1. services/database.py
--------------------------------------------------------------------------------
Path: servers/fastapi/services/database.py
Responsibilities:
  - Creates the async SQLAlchemy engine (sql_engine) from the database URL
    (SQLite or PostgreSQL/MySQL via env config).
  - Creates async_session_maker (expire_on_commit=False).
  - Provides get_async_session() — FastAPI dependency that yields an
    AsyncSession per request.
  - create_db_and_tables() — creates all SQLModel tables if Alembic migrations
    are not enabled (uses SQLModel.metadata.create_all with an explicit table
    list of 14 tables).
  - dispose_engines() — disposes the engine pool on shutdown.
Key Dependencies:
  - sqlalchemy.ext.asyncio (AsyncEngine, create_async_engine,
    async_sessionmaker, AsyncSession)
  - sqlmodel.SQLModel
  - All 14 models.sql.* models
  - utils.get_env, utils.db_utils
Execution Flow:
  Module load: engine + session_maker created. Per-request: get_async_session()
  is injected via Depends() into endpoint signatures. On startup:
  create_db_and_tables() is called from lifespan. On shutdown: dispose_engines().
Role in System:
  - Central database infrastructure. Every endpoint that touches SQL depends
    on get_async_session.

B2. services/documents_loader.py (DocumentsLoader)
--------------------------------------------------------------------------------
Path: servers/fastapi/services/documents_loader.py
Responsibilities:
  - Multi-format document ingestion orchestrator. Given a list of file paths,
    loads and extracts text from each file.
  - Dispatches by file extension:
    - PDF: load_pdf() — detects scanned PDFs (via pdfplumber text sampling),
      uses LiteParse for OCR/text extraction; optionally renders page images.
    - Text files: load_text() — direct file read.
    - Office files (.docx/.pptx/.xlsx/.odt): load_office_document() —
      delegates to office_document_service.extract_office_document_text.
    - Image files: load_image() — converts to PNG via
      DocumentConversionService, then parses with LiteParse (OCR).
    - Other: _parse_with_liteparse() — fallback to LiteParse.
  - clean_extracted_document_text() — strips LiteParse JSON wrappers.
Key Dependencies:
  - pdfplumber, services.document_conversion_service, services.liteparse_service,
    services.office_document_service, services.temp_file_service, utils.ocr_language
Execution Flow:
  1. Constructor resolves file paths via TEMP_FILE_SERVICE and determines OCR
     language from presentation_language.
  2. load_documents(temp_dir) iterates files, dispatches by extension.
  3. Each file's extracted text is cleaned and appended to self._documents.
  4. For PDFs with load_images=True, page images are rendered to temp_dir.
Role in System:
  - Core of the document ingestion pipeline. Called by:
    - api/v1/ppt/endpoints/files.py (decompose_files)
    - api/v1/ppt/endpoints/outlines.py (stream_outlines)
    - api/v1/ppt/endpoints/presentation.py (generate_presentation_stream)
    - services/chat/service.py (readSourceDocuments tool)

================================================================================
C. LLM ORCHESTRATION PIPELINE (HOW PROMPTS BECOME SLIDES)
================================================================================

The presentation generation pipeline has these phases:
  1. Presentation creation (metadata + source content)
  2. Outline generation (LLM generates slide-by-slide content plan)
  3. Structure generation (LLM selects layout for each slide)
  4. Slide content generation (LLM fills each layout schema)
  5. Asset generation (images + icons fetched/generated)
  6. Persistence (slides saved to SQL)

D. DOCUMENT INGESTION PIPELINE
================================================================================

The document ingestion pipeline converts uploaded files into text context
for LLM-based outline generation.

Entry Points:
  1. api/v1/ppt/endpoints/files.py — /api/v1/ppt/files/upload
     Uploads files to temp directory, returns temp file paths.
  2. api/v1/ppt/endpoints/files.py — /api/v1/ppt/files/decompose
     Parses uploaded files into text, returns DecomposedFileInfo list.

Pipeline Flow:
  1. File Upload (files.py):
     - validate_files() checks extensions and size.
     - TEMP_FILE_SERVICE.create_temp_dir() creates a sandboxed directory.
     - Files saved to temp dir, paths returned.

  2. File Decomposition (files.py):
     - .txt files passed through directly.
     - Other files: DocumentsLoader.load_documents(temp_dir).
     - Parsed text saved as .txt files in temp dir.
     - Returns DecomposedFileInfo(name, file_path) for each.

  3. Document Loading (DocumentsLoader):
     - Dispatches by extension:
       PDF -> load_pdf(): _is_scanned_pdf() samples pages for text.
         Scanned: _parse_with_liteparse(dpi=300) for OCR.
         Digital: _parse_with_liteparse(dpi=None) for text extraction.
       Text -> load_text(): direct read.
       Office -> load_office_document(): OOXML/ODF parsing via zipfile+XML.
       Image -> load_image(): convert to PNG -> _parse_with_liteparse(dpi=300).
       Other -> _parse_with_liteparse().

  4. LiteParse (LiteParseService):
     - Spawns Node.js subprocess (liteparse_runner.mjs).
     - Passes: --file, --ocr-enabled, --ocr-language, --dpi, --num-workers.
     - Output: plain text (via temp file stdout) or JSON.
     - Handles: PDF, images, and any format supported by @llamaindex/liteparse.

  5. Text Cleaning (DocumentsLoader):
     - clean_extracted_document_text() strips LiteParse JSON wrappers.

  6. Context Injection:
     - Parsed text joined and passed as additional_context to LLM outline
       generation prompt.
     - Also stored in mem0 for later retrieval
       (MEM0_PRESENTATION_MEMORY_SERVICE.store_generation_context).

Dependency Chain:
  files.py -> TEMP_FILE_SERVICE -> DocumentsLoader ->
    [LiteParseService (Node.js) | OfficeDocumentService (Python) |
     DocumentConversionService (PIL)] -> clean_extracted_document_text ->
  additional_context -> generate_ppt_outline (LLM)

--------------------------------------------------------------------------------
E1. mcp_server.py
--------------------------------------------------------------------------------
Path: servers/fastapi/mcp_server.py
Responsibilities:
  - Creates a Model Context Protocol (MCP) server exposing a curated subset
    of the Presenton HTTP API as MCP tools.
  - Loads OpenAPI spec from openai_spec.json.
  - Uses FastMCP.from_openapi() with MCP_ROUTE_MAPS:
    - POST /api/v1/ppt/presentation/generate -> MCP TOOL (generate_presentation)
    - POST /api/v1/ppt/presentation/generate/async -> MCP TOOL
    - GET /api/v1/ppt/presentation/status/{id} -> MCP TOOL
    - Everything else: MCPType.EXCLUDE
  - Auth: PresentonTokenVerifier validates session tokens for MCP HTTP auth.
    Auth enabled only when app auth is configured (not disabled).
  - Auth forwarding: attach_request_auth_header() forwards MCP caller's token
    to FastAPI backend via Authorization: Bearer ***.
  - Runs as separate process on port 8001, pointing to FastAPI at 127.0.0.1:8000.
  - Disabled in Electron desktop mode.
  - 600-second timeout for long-running presentation generation.
Key Dependencies: fastmcp, httpx, utils.get_env, utils.simple_auth
Execution Flow:
  main() -> check is_mcp_server_enabled() -> parse args ->
  create_openapi_api_client() -> create_mcp_auth_provider() ->
  create_mcp_server() -> mcp.run_async(transport="http", host, port).
Role in System:
  - Separate process alongside FastAPI server. Allows external MCP clients
    (like Claude Desktop) to generate presentations via standardized tool
    interface. The MCP server forwards requests to FastAPI with auth headers
    preserved.
