ARCHITECTURE OVERVIEW
--------------------------------------------------------------------------------
Presenton is an open-source AI presentation generator with a Python (FastAPI)
backend and a Next.js frontend. The backend (servers/fastapi/) handles:
  - LLM-orchestrated presentation generation (16 LLM providers)
  - Document ingestion (PDF, Word, PPT, Excel, images via OCR)
  - Template system (v1 schema-first, v2 component-based with 11 element types)
  - PPTX/PDF export via headless Chromium + Puppeteer
  - Image generation (9 providers) and icon search (local vector embeddings)
  - Chat-based presentation editing (23 LLM tool calls)
  - MCP server for external tool integration
  - Webhook event notifications
  - Semantic memory via mem0 OSS (Qdrant + fastembed + spaCy)

The Shothik integration keeps the Next.js frontend unchanged and treats Hermes
as the backend orchestrator. Presenton's architecture informs which backend
components to lift (Tier 1), adapt (Tier 2), or use as inspiration (Tier 3).

KEY FINDINGS
--------------------------------------------------------------------------------
1. The 4-phase generation pipeline (outline -> structure -> slide content ->
   assets) is the core architectural pattern to adopt.

2. Template v2's 11-element discriminated union (text, image, chart, table,
   vector, infographic, flex, grid, container, group, text-list) with JSON
   Schema generation is the most reusable structural asset.

3. The llmai library dependency is the primary blocker for direct code reuse —
   every LLM call site depends on it. Must be replaced with Hermes routing.

4. The Node.js + Puppeteer export pipeline is a critical architectural
   constraint: PPTX/PDF export requires a running Next.js frontend. Shothik's
   frontend stays unchanged, so this pipeline can work if pointed correctly.

5. The mem0 OSS memory system adds heavy dependencies (Qdrant, spaCy, ONNX).
   Hermes should use InsForge's vector search or its own memory system.

6. The Shothik frontend remains unchanged; Hermes replaces presenton's
   FastAPI backend as the orchestrator, with InsForge for DB/auth/storage.
